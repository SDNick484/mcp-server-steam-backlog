# CLAUDE.md

## What this is

`mcp-server-steam-backlog`: an MCP server for Steam Backlog Triage
(`SDNick484/steam-backlog-triage`), through its `backlog_server.py` JSON API. Sibling of the
`mcp-server-*` family that shares code through `mcp-server-shared`, and follows their conventions.

**This is a learning project.** The owner wants to understand how MCP servers are built, so explain the
reasoning behind non-obvious changes instead of only making them.

## Layout

- `src/steam_backlog_mcp/config.py`: settings from the environment (`BACKLOG_URL`, dry run, write rate).
  Unknown `BACKLOG_*`, `MQTT_*` and `DECK_*` names are kept in `Settings.extra` for phase 2 and doctor
- `src/steam_backlog_mcp/client.py`: `BacklogClient` (httpx; ETag cache for the library; API 1 vs 2
  detection from `X-Backlog-Api`; conditional PUTs), `BacklogError` (a `ToolError`), `Conflict` (412)
- `src/steam_backlog_mcp/domain.py`: the dashboard's rules as pure functions: `normalize`, `tag_key`, `play_state`,
  `length_hours`, `len_bucket`, `score_breakdown`, `Filters`/`passes`, `find` (with relaxation), `picks`,
  `next_queue`, `move`, `overview`, `resolve`. No I/O
- `src/steam_backlog_mcp/models.py`: Pydantic output models (each tool's outputSchema) and builders
- `src/steam_backlog_mcp/server.py`: registrations only, in `TOOL_GROUPS` (read, write, export, resources,
  prompts). `AppState` is built in `lifespan()`: once per process over HTTP, once per session in tests
- `src/steam_backlog_mcp/scoring.md`: the couch score spec, served as `backlog://scoring`
- `src/steam_backlog_mcp/doctor.py`: layer-by-layer checks (config, reach, api features, library, access, port)
- `src/steam_backlog_mcp/sim/fake_backlog.py`: wire-level fake of `backlog_server.py` implementing the
  contract (`api=2`) or today's server (`api=1`), with test hooks; `sample_library.json` is generated by
  `scripts/gen_sample_library.mjs` from `backlog.html`'s sample
- `src/steam_backlog_mcp/{remote,logsafe,lookup,ratelimit,tools,tasks}.py` and their tests: shared, synced
  from `mcp-server-shared` at the commit in `shared.lock` (`registry` excluded). `tasks.py` is for phase 2
- `src/steam_backlog_mcp/cli.py`: `serve` (stdio, or `--http` on 127.0.0.1:8486/mcp/backlog), `doctor`
  (`check`), `simulate`, `call`
- `deploy/alpine/`: installer, OpenRC script, `run.sh`, env file, the command on PATH, CI smoke test.
  `contrib/systemd/` and `deploy/docker/` are secondary
- `docs/backlog-api-contract.md`: the interface with steam-backlog-triage (API 2). `docs/handoff-pr-a.md`:
  notes for implementing it there
- `tests/`: `test_contract.py` (fake v2, fake v1 and a real `backlog_server.py` from `BACKLOG_REF` or
  `BACKLOG_CHECKOUT`), `test_domain.py` (score parity with `fixtures/score_vectors.json`, filters, names),
  `test_tools.py` (in-process MCP `Client`), `test_privacy.py`, `test_cli.py`, `test_stdio.py`,
  `test_http_tools.py`, plus the shared tests. Async tests use anyio's plugin

## Rules for changes

- **The MCP never touches the backlog's files.** It's a client of `backlog_server.py`; one writer.
- **The page is the reference.** `domain.py` mirrors `backlog.html`. A scoring or filter change starts in
  steam-backlog-triage; regenerate `tests/fixtures/score_vectors.json` with `scripts/gen_score_vectors.mjs`
  and copy it to both repos. CI fails if the page's `score()` no longer matches the vectors.
- **Picks are ranked by score alone**, like the page (decision D9 in the contract). Never pin Up next first.
- **Writes never guess**: every game argument goes through `domain.resolve`; anything but exactly one
  match returns `not_resolved` with candidates and writes nothing.
- **Every write** honors dry run (before anything is sent), spends from the write bucket after validation,
  returns the previous value, and needs `confirmed=true` past `CONFIRM_OVER` games or to replace a note.
- **No 1:1 route tools**, and nothing that replaces the library, deletes data or touches keys.
- **Errors to the client are generic** (`BacklogError` text written here); upstream bodies, paths and
  addresses only go to the log, which `logsafe` redacts. SteamIDs are a registered secret pattern.
- **Game names and notes are data**: they appear in their own fields, never inside instruction text.
- Every tool has a `title`, explicit annotations, constrained args, a Pydantic output model, and a
  description with `<use_case>`, `<important_notes>` and `<example>`. `test_tools.py` enforces this.
- **Contract changes** go in `docs/backlog-api-contract.md`, the fake, and `test_contract.py` together.
- **Shared files are changed in `mcp-server-shared`, never here**: the `shared-drift` CI job fails on an
  edited copy. Then `python scripts/sync_shared.py --update` here, and commit the files with `shared.lock`.
- **Public repo**: no IPs, hostnames, domains, container IDs, time zones, SteamIDs, notify names, real
  names, personal emails or keys. Placeholders: `7656119XXXXXXXXXX`, `backlog.example.com`.

## Phase 2 (not built)

`backlog_now_playing`: a `tasks.spawn_task` background subscription to the Deck bridge's retained MQTT
state (`deck-ha-bridge/+/state` and availability) with a read-only broker login; the tool answers from the
cache and joins the library by `appid`. Add it as a new group in `TOOL_GROUPS`, its settings in `config.py`
(the `MQTT_*` names already reach `Settings.extra`), and an MQTT check in `doctor`. The MCP never publishes.
